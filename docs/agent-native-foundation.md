# Ownly Agent 原生基础

Ownly 的 Agent 不把一次模型回答当作任务完成。所有主动行为遵循可恢复的六阶段循环：

1. `perception`：接收有来源、有置信度的用户分享、物品事件、设备状态或家庭节点信号。
2. `reasoning`：同时检索支持证据与反证，形成明确标注为 hypothesis 的意图判断。
3. `planning`：只规划与当前证据相称的下一步，不把弱信号升级成外部行动。
4. `authorization`：依据能力等级决定是否需要用户确认。
5. `execution`：通过本地工具或未来 Connector 执行。
6. `verification`：等待回执并更新物品生命周期；调用接口不等于完成任务。

## 分级自主权

| 等级 | 含义 | 示例 |
|---|---|---|
| L0 | 只观察和解释 | 识别闲置、发现价格变化 |
| L1 | 在本地准备材料 | 生成出售方案、维修申请草稿 |
| L2 | 单次确认后产生外部影响 | 发布商品、支付费用、转移所有权 |
| L3 | 按用户长期策略执行低风险动作 | 创建提醒、更新本地清单 |

L3 不是无限授权。公开发布、支付和所有权转移始终属于 L2，预测意图不能绕过用户确认。

## 信号与意图的区别

观察信号必须保存来源。Ownly 当前只接受：

- 用户主动分享
- 物品事件
- 设备状态
- 家庭节点

后台浏览监控等未授权来源会被拒绝。每个意图判断保存证据、反证、置信度和允许动作。低置信度时继续观察；达到阈值后也只进入 L1 准备，不自动对外执行。

## 持久化模型

- `observations` 保存原始信号和数据来源。
- `agent_runs` 保存目标、证据、反证、权限等级、建议动作和六阶段进度。
- `events` 提供面向用户的活动记录。
- `lifecycle_events` 保存物品状态变化。
- `value_events` 保存独立且可审计的价值流水。

这些记录共同构成后续空间图谱、物品护照、动态 UI 和开放 Connector 的底层依据。

## 开源演进边界

- 参考 LangGraph 的持久状态思想，但当前不引入框架依赖。
- 参考 MCP 的能力声明与工具边界，为未来 Connector 预留统一调用结构。
- 参考 OPA 的策略先于执行原则，但当前使用可读的领域规则保持简单。

下一阶段应将 `AUTONOMY_CAPABILITIES` 拆为公开协议 Schema，并为 Connector 增加权限清单、输入输出 Schema、回执和撤销机制。
