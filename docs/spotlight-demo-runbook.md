# Ownly × GOSIM Spotlight Shenzhen 2026 —— 演示执行手册

> 目的：让整条产品叙事可以被任何人按步骤重演，不依赖口头解释。
> 适用：录屏（1 分钟视频素材）、评委在线体验、现场 demo 前彩排。
> 服务：`python app.py`（默认 127.0.0.1:8765，纯标准库，无需第三方依赖）。

## 三、主线 A：40 秒导览（录视频用这条）

`http://127.0.0.1:8765/?tour=1`，或点主页的「▶ 40 秒看完整条主线」。

| 步 | 讲解 | 背后真实发生的事 |
|---|---|---|
| 1 | 安静是默认状态，不是一屏待办 | 调 `/api/reset` |
| 2 | 环境变化：正在离开家，深圳行程 3 小时 40 分后出发 | 调 `/api/context-event` |
| 3 | 不用打开 App，行动自己到达（充电器没进包 / 公司有备用） | 高亮 `departure_guard` 卡 |
| 4 | 每一步都能追问：证据、反证、命中的长期策略 | 展开 Agent 工作台六阶段 |
| 5 | 你只做决定，执行交给它 → 生成清单 + 同步手表 | 执行卡上的主操作 |
| 6 | 本月已经守住 ¥419，处理中的绝不混进已到账 | 打开月度价值账单 |
| 7 | 你只管出发，物品自己就位 | 收尾 |

留白时长写在 `static/app.js` 的 `TOUR_STEPS`（`hold` 字段，毫秒）。要调快慢只改这一个数组。

## 四、主线 B：购买守护 → 出发卡（手动走）

```
点击「查看现在值得处理的事」（scan）
  ├─ 第一轮：5 张守护卡
  │    补货（精华）/ 清洁（座椅）/ 保价（耳机）
  │    退货窗口（投影仪）/ 闲置转售（Switch）
  │    每张卡：证据 chips + 主/次动作 + 「查看 Agent 为什么这样做」
  └─ 处理掉 补货 / 清洁 / 保价 三张后，再点一次 scan
       → 出发卡（departure_card）到达
            标题：出差深圳 · 物品就绪检查
            上下文：明天（动态日期）10:00 · 深圳南山 · 客户提案 / 天气 / 命中数
            清单 4 行：充电器需携带 / 备用充电器应急位（公司工位，不用回家）
                     / 精华无需补货（18% 够用 3 天）/ 防晒建议携带
            动作：生成出差清单（主）/ 出发前再提醒（次）
            执行后：完成卡 + 事件流写入「长期记忆」+ 同步 Watch
再点 scan → 安静（任务只生成一次，处理过不再打扰）
```

> **注意**：出发卡只被「补货 / 清洁 / 保价」三类阻塞，退货窗口和转售卡不阻塞它。
> 「离家卡」是另一个人口（主线 A 的第 2 步）：`/api/context-event` 直接生成
> `departure_guard`，不必先清任务，它就是锁屏上那条通知。两者讲的是同一件事，
> 但进入方式不同——讲的时候别混。

## 五、其他能力（有余力再演示）

- **购前拦截**：输入「我想买一个 65W 充电器，值得买吗」→ Agent 先检索已有物品，
  给出「先别买」，并记下避免支出 ¥169。反馈会进入长期记忆，改变下一次同类判断。
- **闲置转售**：转售卡 → 生成转售资料（标题/描述/成色/价格/图片清单）→ 选渠道 →
  **必须显式授权**才能提交 Demo connector → 模拟售出回执 → 物品退出活跃仓，历史保留。
- **跨设备**：`/watch` 每 3 秒轮询 `/api/watch`，自动显示第一条待处理任务，可一键授权。
  Watch 端不需要任何改动就会跟着新卡片走。
- **授权策略中心**：右上角 ◎。3 种模式（谨慎/平衡/托管）+ 4 条逐项策略
  （¥500 以内保价自动准备、公开发布始终询问、支付与费用始终询问、所有权转移始终询问）。
  切换模式**不会**取消这三类确认——这是刻意的设计边界。

## 六、技术要点（改代码后必读）

- **任务只生成一次的守卫**：`storage.has_task_record(item_id, task_type)`（含已完成）。
  不加这个守卫，scan 会在每次调用时重新生成已完成的任务。重置（`/api/reset`）
  清空全部任务与事件后可重演。
- **两种卡片组件**：`decision_card` 与 `departure_card` 并列，由 `ui_schema.component`
  决定；前端 `app.js renderTask()` 按 component 分支渲染逐项清单
  （`checklist` / `discoveries` / `comparisons` / `checks` 共用同一段渲染）。
  行程样式在 `static/agent-ui.css` 的 `data-tone="trip"`。
- **行程日期是动态计算的**「明天 + 星期几」，演示永不过期。锁屏日期同样跟随真实时间
  （`ambient.js` 顶部）——别写回硬编码。
- **价值账本种子**：`storage.demo_history_records()` 返回两笔历史流水，
  `seed_demo_history()` 以 `source_key` 做 UPSERT，重复调用不会重复计钱；
  日期被钳制在当月，否则月初重置会漏出月度账单。
  `app.py` 在**首次启动**和**每次重置**后都会种，所以新克隆的仓库打开就有内容。
- **导览引擎**：`app.js` 尾部的 `TOUR_STEPS` + `runTour()`；`?tour=1` 自动开始。
  跳过时会唤醒挂起的等待（`tourWake`），不留悬挂定时器。
- **受限 UI Schema**：Agent 输出什么组件和动作，前端才能渲染什么；
  未在 schema 里声明的动作会被服务端拒绝（有单测覆盖）。
- **单元测试**：`python -m unittest discover -s tests`（34 项，含行程到达、防重复、
  价值账本幂等、月初边界）。
